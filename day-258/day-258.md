#  Login Logic
Welcome to **day 258** of 365 days of code - coding every day for a year, little and often

A bit of a frustrating day today. I kicked off by getting the login logic in place and working, but when testing it, I started coming up against 400 errors for the auth API. 

At first I thought it might be that there was a clash between postgres' built in user table and the user table created by better-auth, so I renamed the table to users and dropped the entire dev DB and rebuilt it. I thought I was on to a winner there, but apparently not...

The auth API was clearly happy to receive a call for creating the user, it just doesn't want to sign in...when I started writing this, I hadn't worked it out, but thinking about it in that context, I realised it couldn't be the DB, or better-auth itself, so I must have missed something in the login logic, and...

...I had missed adding the name attribute to the email field, so I wasn't actually getting the name pulling into the form logic, never have I been so happy to get a 404 page! Sometimes you just need to step back and look at things and compare.

Anyway, more tomorrow, I guess I need a page to land on now!
