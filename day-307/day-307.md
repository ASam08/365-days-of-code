#  Update Item UI
Welcome to **day 307** of 365 days of code - coding every day for a year, little and often

Ok, so adding in the update items UI was not quite as smooth as I thought it would be.

First up, I realised I had to pass the categories from the page server component all the way through the different components to the create (edit in this case) item flow. Not a big deal, but a pain to do.

Then I spotted the defaults was having an issue where after submitting an edit, it would revert on the UI side only, even though the DB had been updated, that's because I was getting the data at page open, and resetting to that on submission.

Last up to solve was that the categories field was not showing the current value in the edit flow, until that field was changed. That was a change to the way I handled it in the category field component, as when I wrote it, I never thought about the fact that I'd be using it in edit mode, so no need to pull through anything but a blank.

Anyway, those things all sorted, and I'm really happy with how it's working. My only thought is that I might wantto change it from how it's showing, I end up having a dialog on top of a dialog, so I might change it to a toggle where it changes the open-card to be the edit dialog...thoughts for tomorrow!
