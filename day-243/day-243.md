#  Controlled Colour
Welcome to **day 243** of 365 days of code - coding every day for a year, little and often

One day, someone will (maybe) read my code, and fuss that I spelled colour wrong. That was a thought that popped into my head as I wrote the word colour so many times in my code today, including as constants and states, but that won't be my problem.

Anyway, I worked more today on the implementation of the last used colour per subject piece, today actually implmenting it into the add-block component. I thought I had done it all correctly at first, then realised that it wasn't actually changing the colour in the field. Then I realised there was nothing to make it update, it was loaded initially on page load and that was it. I thought about a few ways to do this, I could reload the colour picker each time, but that's a little heavy to do, so instead I made the colour picker a controlled component.

That meant a little bit of work on the editblock form to control the state in the form instead of in the colour picker, but otherwise it all seems good.

The one thing I do want to take a stab at is to protect against a now possible race condition where someone could change the subject and then changes it again before the colour has updated, which would cause an issue. I guess that is a job for tomorrow!
