#  Check Check
Welcome to **day 289** of 365 days of code - coding every day for a year, little and often

Ok, today's commit doesn't look like alot, but it resembles a whole bunch of sanity testing on the S3 functions that I put in place yesterday. I wanted to test out the pre-signed URL generation and retrieval at a basic level, just to make sure I had my connections correct, and what do you know, I didn't.

I set up a throwaway API route (that I never committed so I never accidentally go back and make it available), and got to testing.

First issue was that I was using localhost in my env variables, but my local machine was converting that to IPv6 instead of v4, so once I changed to the 127.0.0.1, I finally managed to connect. But then I was getting a checksum issue. My understanding of it is that the sdk by default requires a checksum on the data passed into the URLs via PUT, but because I don't know what the data is before it comes in, I'm not generating that checksum on the server prior to trying the upload. I chose to circumvent the checksums piece for now, using a built in prop on the SDK, just so I could prove out the connection, but I think it will be good to remove that later on, and actually generate the checksum before generating the PUT URL, and adding it to the request, for data integrity checks.

Anyway, all working now, and on to the next step tomorrow...
