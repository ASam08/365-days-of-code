#  Jest Bugs - Day 4 - Hooray!
Welcome to **day 249** of 365 days of code - coding every day for a year, little and often

Well thank goodness for that (I'd like to use some stronger words, but not here). After digging and digging and digging, I finally found it. Was it a Jest thing? No. Was it an Autocomplete thing? No. Was it a transitive dependency that I didn't even really know was there? Why yes, of course it was!

Nwsapi, jsdom's CSS-selector-matching engine, went from 2.2.24 to 2.2.27. Jsdom itself is pinned to the exact to a specific version (26.1.0), and jsdom depends on nwsapi via the loose range ^2.2.16. For some reason pnpm-lock.yaml picked up a newer nwsapi patch simply because it was regenerated. Now, do I know what it is about nwsapi v2.2.27 that the Autocomplete tests didn't like? Hell no. Also, I'm now sick of these "ask myself questions thing, it's becoming too much in this update".

Anyway, I pinned the version back to 2.2.24, re-ran my tests and happy days, everything worked. I then made the call to undo all of the testing and changes from the last few days, so I checked out the initial commits for this branch, committed them as a new commit, repinned the nwsapi and re-allowed the @parcel package to runs scripts (remember days ago when I first started looking at this PR), re-tested, and we were off and running.

Funnily, dependabot had actually pulled through new package updates today, so it had closed off the PR in lieu of a new one with even more updates. Rather than mess with that to start with, I just created a new PR for this branch, merged it and then got dependabot to rebase the new branch/PR.

That second one tested through fine all by itself first time, so I made the call to merge that, and *finally* push the release.

Phew, I guess check in tomorrow where hopefully normal service will resume...
