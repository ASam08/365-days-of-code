#  What Do You Mean "User Not Found"
Welcome to **day 241** of 365 days of code - coding every day for a year, little and often

Well, it turns out that a few days ago, I broke prod, and didn't even know...

So in my last release I included a package bump for about 8 packages, one of them being Better Auth to v1.7.1. Now, I had seen that going past v1.7.0 did have breaking changes, and I looked at them in the release notes and thought I was ok, turns out I was wrong. Since that release, all logins have been failing and I had no idea. It was only when I tried to log into my own self-hosted instance this morning that I found it wouldn't let me in, with the logs saying "User Not Found". Cue me doing a bit of a deep dive, check the db, did that get wiped, no, user is still there, with the right email address, what the hell?

I hadn't noticed this on my dev instance as I already had a logged in user that I was testing with, I had no need to log out and in again. Jest tests had picked up nothing, neither had the build.

Anyway, I remembered the Better Auth breaking changes and took a closer look, this time at their migration page on their website (big clue, if there is a migration page, you normally have work to do).

Now, the actual work to change it was not all that hard, a db migration, add in some custom lines to actually fill out the values needed, then one extra line of code in the auth file and all is right with the world. I won't go in to the whole details of what needed changing, and why, [Better Auth already did that](https://better-auth.com/docs/guides/1-7-upgrade-guide#migrate-from-16-to-17), but needless to say, it's a bit embarrassing that it took me so long to realise it was broken.

But we live and learn, the PR is merged, release is out and all should be right with the world again (phew).

You may be wondering what happened to my goal of getting 100% coverage on the accountform component from yesterday? Well obviously I had more important things on, so I merged the PR as is (it's the same missing branch in coverage from before the feature anyway), and it's included in the new release (hooray).

Anyway, more tomorrow!
